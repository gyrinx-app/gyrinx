{% comment %} djlint:off {% endcomment %}{% comment %} The fighter status badge cluster: injury state, then Captured or Sold to Guilders. Replaces the 35-line, seven-badge block in core/includes/fighter_card_content.html and the single badge in list_fighter_state_edit.html and list_fighter_injuries_edit.html. It exists because a caller writing this by hand gets it WRONG, not merely because the markup repeats. The original expresses a three-way permission/mode matrix by duplicating each badge as either an anchor or a span; it restates the injury colour cascade three times; and the cascade has no else branch, so any injury_state added to the model in future renders a badge with no background at all. Here the colour comes from c-badge's state table, which is total over the model's choices and is tested to stay that way. Props fighter ListFighter or virtual fighter. Required. Pass it dynamically -- fighter="{{ fighter }}" stringifies the object and every lookup then fails silently. show_state On by default. Pass show_state="" to suppress the injury badge entirely. This exists because the two badge groups are gated DIFFERENTLY in the original: the injury badge is campaign-mode-only, the capture badge is not. is_captured is a plain property over a persistent capture_info relation, so a gang that has left campaign mode keeps its captured fighters and must keep their badge. Hoisting both under one {% if list.is_campaign_mode %} silently loses it. show_active Off by default, so an active fighter renders no injury badge, matching the fighter card. The state-edit and injuries-edit pages always show the current state and pass show_active to get the green Active badge. show_capture On by default. Pass show_capture="" to suppress the Captured / Sold-to-Guilders badge. The state-edit and injuries-edit pages render exactly one badge today and must keep doing so. state_href Already-resolved URL. When it is a safe root-relative path the injury badge is a link; empty (or unsafe) gives a span. Permission, print and compact gating stays at the call site, where the view context lives. This is deliberately a URL and not a can_edit flag -- the component must not encode who is allowed to do what. LOOP HAZARD: do not write {% if can_edit %}{% url ... as u %}{% endif %} inside a for-loop. ForNode pushes context once for the whole loop, so a value assigned on one iteration survives into later iterations where the guard is false, and rows the viewer cannot act on get action links. Assign unconditionally and gate in the attribute instead: {% url 'core:x' a b as u %} captured_href Already-resolved URL for the captured / sold badge. Same rules. class Applied to every badge rendered. The estate uses ms-2: adjacent badges are separated by that margin, never by a literal space. Renders nothing at all for an active, uncaptured fighter. A fighter who is both dead and captured renders BOTH badges, exactly as the original two independent {% if %} blocks do. Pages whose cascade renders only one badge (list_post_battle_updates.html) must not use this component. Whitespace: no trailing newline -- see the note in badge.html.
