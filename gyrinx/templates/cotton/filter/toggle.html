{% comment %} — "narrow this list to only X." The filter switch: 15 in the estate ("Your Lists Only", "Archived Only", "Subscribed Only", "Include restricted", "Show illegal"...). Three things it gets right that hand-rolled switches keep getting wrong: 1. THE OFF VALUE. An unchecked checkbox submits nothing, so a filter that is ON by default cannot be turned off without a paired hidden input carrying the off value. Several sites remember this; several don't. Here it is emitted automatically whenever `off_value` is set (default "0"), immediately before the checkbox so the browser's last-value-wins rule resolves it correctly. 2. NO JAVASCRIPT REQUIREMENT. `submit_on_change` adds the `data-gy-toggle-submit` hook that the shared filter JS listens for — an enhancement. Without JS the switch still submits with the form's own button, and the resulting state is still a URL. Compare `onchange="this.form.submit()"`, used at 3 sites, which is CSP-hostile and inlines behaviour into markup. 3. `.form-check > input + label` as DIRECT, ADJACENT children — styles.scss's `.form-check > label { @extend .form-check-label; }` depends on it.
