Owns the connector arrow and the wrapper. {# inline: br + arrow + links #} Cost{% dot %} Delete ... {# inside a stat table #} TWO SHAPES, because the estate has two. The weapon menu is a full table row whose td spans the stat columns and whose links sit in a flex box; the gear and stash menus are ordinary inline flow after a br, directly beneath the item they act on. They are NOT interchangeable: giving the inline form a d-flex wrapper turns it into a block-level box and it stops sitting on the line under its subject. SEPARATORS STAY AT THE CALL SITE. Every real menu has conditional links (upgrades only when there are upgrades, Sell only in campaign mode), and a component cannot see which of its slot children rendered, so it cannot know where a separator belongs. Writing the separator between links keeps that decision next to the {% if %} that causes it. A CSS ::after separator would put the dot inside the anchor, making it underline and take the hover state. NOTE the estate is inconsistent here and this component does not resolve it: most menus separate with {% dot %} ( · ) but fighter_card_stash.html uses a bare ·, which has no non-breaking spaces and so can break across lines. Left as-is per call site to keep this migration byte-identical; worth a follow-up decision.
