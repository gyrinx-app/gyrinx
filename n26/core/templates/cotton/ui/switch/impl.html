{% comment %} OVERRIDE of django_cotton_ui's cotton/ui/switch/impl.html. Identical to the shipped template except for how the hidden checkbox is bound. --- what was wrong --- The kit binds the checkbox with `x-bind="input"`, an object holding `x-model.boolean`. Applied that way the model never reflects onto the element: once Alpine initialises the component the checkbox reads `checked` and stays that way, whether the switch was started on or off, and whichever way the state moves afterwards. The visible track follows `switchOn` correctly, so the control looks right and posts the opposite. A form is what makes that dangerous rather than cosmetic. Saving a weapon after editing its price marked it exclusive, because the box under the switch had been checked since load and nobody could see it. --- why it stayed hidden --- Every form in the app was unbound until things could be edited, and an unbound field's value is `None`, which renders `switchInput(false, none)` — `none` is not a JavaScript literal, so the component threw on init and never bound anything. The plain unchecked input underneath was what got posted, which is the right answer for the wrong reason. The first form opened on a saved row is the first one where Alpine got far enough to be wrong. --- the change --- `x-model="switchOn"` on the element itself, which is the ordinary Alpine spelling and reflects both ways, plus the `x-ref` and `:disabled` the bind object was also supplying. No `.boolean`: that modifier casts a string value, and this state is already a boolean. --- upstream --- Delete this file if the kit fixes its binding, and check the rest of the template against the shipped one when you do — everything below the input is a verbatim copy and will drift. {% endcomment %}
