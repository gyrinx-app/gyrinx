{% comment %} — a list of things to tick, grouped under its headings. Takes the same n26.render.ChoiceOffer that draws: groups with names, options with a line of detail. A sibling of that component rather than a mode of it, for the reason radio cards and checkbox cards are siblings — one of many is the browser's rule over a shared name, any number is the absence of that rule, and the two say different things about what leaving a box alone means. One name across every group all the same: the headings are how the list is read, not a question each. Checkboxes and no script. What is ticked when the page arrives is what the server said, and a box that submits nothing has been cleared — so the form works before anything runs and stays right if nothing ever does. An option the rules grant is drawn ticked and fixed, saying what grants it: nothing stored is behind it, so there is nothing a click could take away. A fixed box submits nothing either, which is why whatever applies the difference must leave granted things out of it rather than read their silence as a clearing. Rows rather than cards: this draws inside a box beside a model's card, where a grid of cards would be a second page. An empty offer draws nothing — whether to say something instead depends on why it is empty, which the page knows and this does not. :offer — a n26.render.ChoiceOffer. name — the input name every box submits under. One name across every group. {% endcomment %}
