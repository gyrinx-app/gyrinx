Beside, for the short comma-joined lists that make up most of a reference card, where stacking would spend a line on every heading. Above, for prose, which reads badly squeezed into whatever width a heading left it. The beside form wraps its label to its narrowest — one word per line — so a long label like "Legendary Names" costs two short lines rather than reserving a wide column and starving the value. `aligned` is the opposite trade: a fixed label column, for a run of entries whose values should start at the same x. The entry is monolithic: an atomic inline-level box, which no fragmentation engine is permitted to split. See print.css for why that beats asking with break-inside, and for the one case where it is blockified back to an ordinary flex row. label — the heading. Omit it and the value stands alone, still on its own line. stacked — label above the value. aligned — fixed-width label column instead of a shrink-to-fit one. label_width — that column's width.
