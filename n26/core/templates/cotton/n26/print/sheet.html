It publishes the geometry as custom properties — --print-content-w and --print-content-h — which the grid divides into cells, the guides draw folds from, and @media print pins the width to. One set of numbers, read by everything downstream, so a change to the margin cannot leave a hardcoded width behind. That is not hypothetical: v1 carried a `width: 204mm` that had to be kept in step by hand with `@page { margin: 3mm }`, two numbers for one fact. **Exactly one sheet per document.** @page is a document-level rule with no element to scope it to, so a component that claims to own the page has to be the only one making the claim. Two sheets on a page means the second one's @page silently wins for both. Where you genuinely need several — a gallery showing sheets as examples — `owns_page=""` turns the rule off and leaves a sheet that is only a correctly-measured box. It is then a preview of paper rather than paper, which is exactly why the print lab puts the real thing in an iframe: its own document, its own page. The sheet renders at its true physical size on screen as well as on paper, so what you see is the artefact rather than an impression of it.
