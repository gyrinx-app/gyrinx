Takes EditableStatCells, not a Django form, for three reasons: the pairing of a statline type with a bound form is display logic and belongs in Python; the gallery must render on an empty database, which a real form cannot; and a component in this app has no business knowing what the authoring forms look like. Values are shown as they are stored, which is canonical — a Movement of four reads 4" in the box as well as on the card. Nothing here formats anything, and nothing here decides what an empty box means; both belong to whatever saves the form. The boxes are built from the kit's input tokens rather than from c-ui.input, for the reason this family does not build on c-ui.table either: the control writes its own class attribute, so a class from the call site lands as a second one and the browser keeps whichever it reads first — there is no way to centre the text or narrow the box without losing the rest of the styling. Both matter here. Scrolls horizontally rather than wrapping, for the same reason the display strip does: thirteen boxes do not fit a phone, and a statline that reflows stops reading as a row. Errors sit under the table, one line each, because a characteristic cell is a few characters wide and there is nowhere in the row to put a sentence.
