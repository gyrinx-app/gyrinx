{% comment %} — a set of characteristics as a table. {# one strip: a weapon profile, or a fighter where space is tight #} {# the rulebook's layout: a row pair per group, Type and XP filling the rest #} Two layouts, because the book uses two. `strip` puts every characteristic on one row, which is what a weapon profile wants and what fits a dense list. `book` breaks at each group — so M–Sv sits above Ld–Int, exactly as printed — and spends the second row's leftover columns on the type line and XP, which is what the page in the rulebook does rather than leaving them empty. Either way the grouping comes from is_first_of_group on StatlineTypeStat, so where the row breaks is content. The same is true of the tint, from is_highlighted: the psychology stats stay together and stay emphasised whatever a pack does to the rest. Not built on c-ui.table, the one kit component a card could not reuse. A statline is a centred characteristic strip where that is a left-aligned data grid with per-row borders and row hover — and its styling is applied through descendant variants, [&_th]:text-ink-500 and the like, which outrank any class put on a cell, so the look cannot be adjusted from the call site at all. Composing from the same tokens gets the strip a card actually wants. Scrolls horizontally rather than wrapping: thirteen characteristics do not fit a phone, and a statline that reflows stops being readable as a row. XP is two numbers, given separately rather than as the "61/79" one string a printed card gets. They are not the same kind of fact — one is where the fighter is and the other is where the next rank is — and a card that hands over the joined string has thrown away which is which before the template can say so. Apart, the target can be muted and each can carry a tooltip naming it. :statline — a n26.render.Statline. layout — strip (default) or book. type_line — book only; the second row's trailing cells. xp — what the fighter has now. xp_target — the next rank, muted beside it.
