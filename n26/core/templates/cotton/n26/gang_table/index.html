{% comment %} — the gangs you own, searchable. --- it is not a --- Called a table because that is what it is to a reader, and built as a list of grid rows because a real one cannot survive a phone. Four columns, one of them a four-figure wealth strip and one a pair of buttons, is more than 390px holds; the usual escape is `display: block` on the cells, which throws away the alignment that made it a table in the first place. A grid keeps both: one column on a phone with the row's parts stacked, and at md the same rows snap into columns that line up down the page. Nothing is hidden at either width — a gang's worth is why you are looking. --- the controls --- The same bar uses, and the same components: the search takes its own line and the menus wrap under it. Whatever a reader learns about filtering the trading post is true here, which is the entire argument for not inventing a second arrangement for the second list on the site. Type is a rather than its multi-select sibling because it is one question with one answer. Rows register their facets on init and show themselves only while those pass, so the count and the list are computed from one object and cannot disagree. --- two searches, one box --- The box narrows what is on the page as you type; pressing Search asks the server, which can reach gangs this page never carried. Given an `action` it does both: typing is the fast answer to a question the page can already answer, submitting is for when it cannot. `query` is what the server was asked, and the box opens holding it. That is also what keeps the two out of each other's way: while the box still reads what the server answered, the in-page filter passes every row, because the rows on the page *are* the answer — narrowing by that query again would hide any row the server matched by means a substring does not have (a word stem, a field the row does not print). Type something else and it narrows from there as usual. :type_options — [{value, label}] of every gang type present. Drawn only when there are two or more: a filter with one option filters nothing. noun — what the count counts. "gangs" by default. action — where Search submits, as a GET. Without one there is nowhere to go and the submit does nothing; the box still narrows in place. :query — the query the server answered, echoed back into the box. Pass it as an expression: through an attribute it is escaped twice and a quote in the query comes back as `&quot;`. empty — what to show when a search matches nothing. {% endcomment %}
