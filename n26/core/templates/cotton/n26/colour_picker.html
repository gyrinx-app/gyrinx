{% comment %} — pick a colour from the palette, or none. A grid of swatches, one radio each. Radios and not a select, because the whole question is "which of these looks right" and a dropdown makes you open it, read twenty words and close it again to compare two. Laid out as a grid so the answer is a glance. --- none is an option, not the absence of one --- The first swatch is None, and it is a real radio with a real value. A picker whose default is "nothing selected" cannot be *returned* to nothing once you have touched it — you would have to reload the page — and it also cannot tell "no colour" apart from "not answered yet", which matters the moment this is inside a form that redisplays after an error. --- the swatch is the control --- Each radio is sr-only and the swatch beside it is what you see, styled through peer-checked. That is a label wrapping a real input, so it is keyboard-reachable, arrow-keys between options like any radio group, submits without JavaScript, and reads out its colour's name to a screen reader. Nothing here is a div pretending. --- why a lookup and not bg-{{ name }}-500 --- Tailwind reads class names as literal strings; a class built from a variable is a class it never sees and never emits. app.css force-emits the palette via @source inline() so the utility exists, but the honest way to be sure is to write the class out. Same reason c-ui.badge keeps its own dict. The named hues are fixed; ink follows the theme's neutral scale, so it is the one swatch that changes with light and dark. name — the form field name. value — the colour currently chosen. Empty means None, which is the default. label, description — the fieldset's legend and the line under it. Optional. colours — the palette, if you want a shorter one. Names must be keys of swatches; anything else renders as an empty box, which is the failure you want rather than a page that will not load. {% endcomment %}
