{% comment %} — a strip of tabs that are links, one of them current. A tab strip for a choice the server answers. Each tab is an , so the choice is a URL: linkable, in the history, and made by a browser that has run no JavaScript. The kit's c-ui.tabs is the other kind — panels already on the page, switched in the hand — and cannot be this, because the thing behind a tab here is a whole render. Which is also why a tab carries no count. Only the current tab's contents have been fetched; a number on the others would mean building them too, and a strip that costs a query per tab is a strip that gets worse the more choices it offers. Counting belongs inside whatever the chosen tab drew. Drawn as a nav rather than with role="tablist": these navigate, and a reader told "tab" by a screen reader expects arrow keys and a panel that swaps under them. aria-current="page" says which one they are on. It wraps rather than scrolling sideways. Names come from content and can be long, and a horizontal scroller on a phone hides the tabs past the edge behind a gesture nobody is told about — two rows of tabs are plainer than one row with something off the end. A single name too long for the width truncates instead of pushing the strip wider than the page. The rule under the strip is drawn by the tabs themselves: every tab carries the same 2px bottom border and the row makes them one height, so the borders land on the same pixels as one continuous line — accent under the current tab, box border everywhere else. The trailing span carries it across the width the tabs do not fill. :tabs — [{label, href, current, title}]. `title` is optional and is the full name when `label` has been shortened to fit; it becomes the link's tooltip. label — what the strip is choosing between, as its accessible name. speculate — ask the browser to start on the other tabs before they are clicked, so a strip whose every choice is a whole page-build answers a click with the expensive part already paid. "prefetch" fetches the HTML — the server's work, which is most of the wait — and holds only bytes; the click still parses and boots the page. "prerender" builds the whole hidden page, so the click is instant — but each one is a full document, DOM, scripts and all, held in memory behind the page being read, and a strip of heavy pages can hold several pages' worth. Prefetch is the safe spelling; reach for prerender only where the pages are light. Off by default: only a call site knows whether its pages are worth paying for before anyone asks. Browsers without speculation rules ignore the hint — the tabs are ordinary links either way. The speculative request reaches the server with a `Sec-Purpose: prefetch…` header, which analytics already ignores; these tabs must stay side-effect-free GETs, which they already had to be to be links. eagerness — when to start. "moderate" (the default) waits for intent — hover, or touch-down — so nothing is fetched for a tab nobody moves towards; "immediate" starts as soon as the page settles, which buys the most head start and spends the most server work on pages that may never be opened. {% endcomment %}
