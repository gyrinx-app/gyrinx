{% comment %} — a long handed in is what the browser submits, untouched: same name, same option values, same selected options. Nothing here mirrors the value into a second input, and nothing rewrites what a row is worth — the panel sets `selectedIndex` or flips `option.selected` on the real element, and the form posts what it always posted. A picker that carried its own copy of the value would be one refactor away from posting a label where a primary key belongs, and the failure would look like a form that saved the wrong row rather than like a broken control. The index is what is set, never `select.value = …`: two rows may hold the same value, and assigning a value picks whichever comes first. --- with no script --- The select renders visible and complete. The panel is x-cloak'd and shown only once Alpine has run, and hiding the select is something Alpine does on init — so a reader with no script gets the plain select they would have had, working, with no filter box sitting above it swallowing typing.
