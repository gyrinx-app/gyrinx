How this app is put together

The examples are the source. Each one is a real template file under designsystem/templates/designsystem/demos/. The page includes that file to draw the preview and prints the same file's text underneath, so the code you read is by construction the code that produced the picture. Drop a new file in a component's folder and it shows up here — no registration step.

The prop tables are read, not written. Every component declares its API in a <c-vars> block, and most explain themselves in a comment underneath. Both are parsed out of the installed package at request time, so upgrading django-cotton-ui updates this documentation rather than silently invalidating it.

The button that makes something is green. A control that brings a thing into existence — create a gang, found a campaign, add a fighter — is variant="success". One that saves an edit or goes somewhere is primary, and one that destroys something is danger. Three colours for three kinds of consequence, so the committing action on a form can be found without reading the words on the buttons. Use the variant, never the utility class: a screen reaching for bg-green-600 gets the colour and none of the meaning.

Help text is body size. A label, a lead, a field's help and a section's description are all set at the page's own size and made quiet with colour instead. Small text is for what a reader is meant to scan past — a column header, a unit, a caption on a number that already speaks for itself. This is a house rule and it overrides the kit, which sets c-ui.description at text-sm — see the override in templates/cotton/ui/. If you are reaching for a smaller size, say in the component's comment what makes this the exception.

The gallery shares the kit's tokens. Its own chrome is built from --color-ink-*, --color-surface and the radius scale, so a theme change moves the whole page and you can judge a palette in context instead of against a fixed white frame.
