Theming

Cotton UI is themed entirely by CSS custom properties, so a theme is a short block of variable overrides rather than a rebuild. Pick a preset below and the whole gallery changes — this page included.

{# ---------------------------------------------------------------- presets #}

Presets

These drive the kit's own theme builder — the paintbrush in the bottom-right corner — rather than being a second, competing set of controls. So a preset is a starting point: apply one, then open the widget to adjust any single dial, and use its Copy CSS button to take the result away. Your choice persists as you browse.

Making a theme permanent

The widget writes to <html> and remembers your choice in localStorage — that is a preview aid, not a deployment mechanism. To keep a theme, copy the CSS it generates into your own stylesheet after the Tailwind import. It looks like this: 

@import "tailwindcss";
@import "./cotton-ui.sources.css";

:root {
    --color-accent: var(--color-indigo-500);
    --color-accent-content: var(--color-indigo-600);
    --color-accent-foreground: var(--color-white);
    --radius-control: 0.25rem;
    --radius-box: 0.375rem;
}

.dark {
    --color-accent: var(--color-indigo-400);
    --color-accent-content: var(--color-indigo-300);
    --color-accent-foreground: var(--color-indigo-950);
}

Two things are worth noticing. The accent is set separately per mode, because a 500 that reads well on white is usually too dark on near-black. And the neutral scale is retoned by reassigning --color-ink-*, never by overriding zinc itself — that indirection is what keeps your own zinc-* classes doing what they say.
