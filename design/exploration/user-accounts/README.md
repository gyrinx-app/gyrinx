# User accounts redesign

The application implements the account redesign at `/user/@<username>/`.
This directory documents the application change; it is not a standalone prototype.

## Profile behaviour

- A circular picture appears beside the name, joined date, role and location.
  Empty pictures use a grey circle with Lucide's circle-user icon. The location
  line is limited to 20 characters, uses map-pin and displays “None specified” when blank.
- Owners open the React editor directly from the cog or picture. Picture editing
  uses the N26 Cropper.js flow with a circular preview and the shared server-side
  image pipeline. Uploads are limited to 10 MB and stored as bounded square JPEGs.
- Three general link/email slots accompany Instagram and Discord handles.
  Instagram produces a profile URL from the handle. Discord accepts an optional
  numeric user ID: with it, the handle links to the account; without it, the handle
  is shown as text. Empty contacts are omitted, with dots between displayed ones.
  Older fourth/fifth general links survive edits until explicitly removed.
- The standard gang palette supplies the profile's highlight colour.
- N23 categories match its homepage: Campaign Gangs, Campaigns, Lists and Content
  Packs. Lists combines public and owner-visible unlisted lists, marked Unlisted.
  Existing public-gangs/unlisted category addresses resolve to Lists.
- N26 retains Gangs and Campaigns. Category tabs show counts, with seven records
  per page. Gang lists sort by name, last modified or wealth. Edition, category,
  sort and page are server-owned URL state.
- Gang entries reuse the homepage Cotton row, artwork, colours and wealth strip.
  Public profile rows omit owner actions. Campaign context follows each edition's
  visibility rules; private records remain hidden from unrelated viewers.
- Eligible viewers see “Invite to N26 campaign”; only superusers may impersonate.
  These actions occupy their own header row to keep the identity readable.

## Implementation

`gyrinx/accounts/public_profiles.py` owns the shared presentation and prepared
contact data. Edition readers in `n23/core/public_profiles.py` and `n26/profiles.py`
own queries and visibility. Roster counts use correlated subqueries; artwork is
cached by gang type during each read. Sorting uses the same totals as the strip.

`gyrinx/accounts/profile_settings.py` owns validation and the native multipart
POST. Only the profile owner receives editor props or can save. Signed starting
state and a row lock protect against stale edits. Validation preserves the draft;
conflicts require a reload. Cancel restores the initiating control's focus, and
back-forward restoration after submission reloads fresh profile state.

`gyrinx/accounts/migrations/0005_public_profile_settings.py` and
`0006_profile_social_accounts_and_location.py` add fields to profiles and history.
`0007_location_20_characters.py` caps both current and historical location fields.
The image pipeline and palette live in `gyrinx/images.py` and `gyrinx/colours.py`;
the existing N26 modules re-export them. Cotton recipes are regenerated by the
frontend exporter; generated CSS, recipes, bundles and captures are ignored.

## Development and verification

Use the worktree environment described in the repository instructions:

```bash
.codex/run.sh manage agent_login_url /user/@agent-user-accounts/ --username agent-user-accounts
.codex/run.sh pytest gyrinx/tests/test_profile_settings.py gyrinx/tests/test_public_profiles.py n26/tests/test_user_profiles.py n23/core/tests/test_user_profile.py n26/core/test_images.py n26/core/test_colours.py n26/frontend/tooling/test_export_cotton_recipes.py -n 4
.codex/run.sh npm run test:react
.codex/run.sh npm run typecheck
./scripts/fmt.sh
```

Validation on 11 November 2026 passed 128 focused Python tests and all 752 React
tests, plus type, build, format and migration-state checks. The migration overlap
checker found no conflicts with upstream's new N26 migrations. The contribution is based on upstream `13612ee4`; the shared input retains its
large-control support alongside the profile picture styling.

The isolated local demo contains 20 of each previous category; merging public and
unlisted lists produces 40 owner-visible Lists and 20 for other viewers. Browser
checks cover desktop/phone layouts, settings, crop/save, metadata, sorting, tabs,
pagination, Back, empty pictures and administrator/arbitrator visibility. No
production data was modified. Captures remain under `screenshots/user-accounts/`
and are attached to the pull request rather than committed.
